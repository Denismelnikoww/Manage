**Статус:** Выполнено
**Связанные задачи:** 2.1.2 (Dockerfile и docker-compose.yml), 5.1.2 (smoke-тесты окружения)
**Связанные документы:** [[Схема базы данных (ERD)]], [[Definition of Done]]

## 1. Цель работ

Подготовить воспроизводимое изолированное тестовое окружение с PostgreSQL, пригодное для функционального, интеграционного и регрессионного тестирования LabFlow, и убедиться, что окружение поднимается на «чистой» машине одной командой.

## 2. Состав окружения

| Компонент | Реализация | Порт | Назначение |
|---|---|---|---|
| PostgreSQL | `postgres:16-alpine` | `5432` (переопределяется `POSTGRES_PORT`) | Основная БД тестового контура |
| Backend | FastAPI, образ из `./backend` | `8000` | API, Swagger — `/docs`, health-check — `/health` |
| Frontend | React (Vite), образ из `./frontend` | `3000` | Пользовательский интерфейс |
| Оркестрация | Docker Compose | — | Единая команда запуска и изоляция от хоста |

Параметры БД по умолчанию (`.env.example`):

- пользователь — `labflow_user`;
- пароль — `labflow_secret_password`;
- база — `labflow_db`;
- volume — `postgres_data` (данные сохраняются между перезапусками).

## 3. Ход выполнения

### 2 ноября — подготовка

- Проверены требования к рабочему месту: Docker Desktop, Docker Compose v2, свободные порты `5432`, `8000`, `3000`.
- Создан локальный `.env` на основе `.env.example`; секреты и пароли не коммитятся в репозиторий.
- Проверена конфигурация `docker-compose.yml`: для PostgreSQL задан `healthcheck` (`pg_isready`), backend стартует только после `service_healthy`.
- Зафиксирован порядок запуска: `postgres` → `backend` → `frontend`.

### 3 ноября — развёртывание и проверка

- Выполнен запуск окружения на чистой машине: `docker compose up --build -d`.
- Проверен статус контейнеров и health-check PostgreSQL.
- Выполнено подключение к БД через `psql` из контейнера.
- Проверено автоматическое создание схемы при старте backend (`Base.metadata.create_all`).
- Выполнена проверка сохранности данных: перезапуск контейнера и повторный запуск compose.
- при обычном docker compose up Compose сначала поднимает postgres, дожидается статуса healthy и только затем запускает backend — порядок запуска postgres → backend → frontend соблюдается;

## 5. Замечания и ограничения

| № | Замечание | Влияние | Решение |
|---|---|---|---|
| 1 | Порт `5432` может быть занят локальной СУБД на машине разработчика | Окружение не стартует | Использовать `POSTGRES_PORT` в `.env` (например, `5433`) |
| 2 | Пароли по умолчанию подходят только для локального контура | Риск при переносе в общий/staging-контур | Для staging задавать отдельные секреты, не использовать значения из `.env.example` |
| 3 | MinIO заявлен в `.env.example`, но отсутствует в текущей версии `docker-compose.yml` | Нельзя проверить загрузку отчётов в рамках этого контура | Вынести в риск для 5.1.2; проверка загрузки файлов — после добавления сервиса MinIO |
| 4 | Автосоздание схемы через `create_all` не заменяет миграции | При изменении моделей возможны расхождения схемы | На этапе развития — перейти на Alembic, для MVP зафиксировать как технический долг |

# Отчёт по задаче 5.1.2 — Smoke-тесты окружения

**Задача ИСР:** 5.1.2. [QA] Smoke-тест-кейсы развёртывания (`docker compose up` на чистой машине)
**Исполнитель:** Кулов Дамир (роль: QA)
**Дата выполнения:** 6 ноября 2026 г.
**Статус:** Выполнено
**Окружение:** локальный Docker Compose-контур (PostgreSQL 16 + FastAPI + React)
**Связанные задачи:** 2.1.3 (тестовое окружение PostgreSQL), 5.1.1 (тест-план)
**Связанные документы:** [[Definition of Done]], [[Спецификация API (OpenAPI)]]

---

## 1. Цель

Проверить, что тестовое окружение после чистой сборки и запуска пригодно для дальнейшего функционального тестирования: все сервисы стартуют, ключевые точки входа доступны, БД подключена, данные сохраняются, явных ошибок в логах нет.

Smoke-набор выполняется перед каждым прогоном функциональных и регрессионных тестов.

## 2. Проверяемое окружение

| Компонент | Ожидаемое состояние |
|---|---|
| PostgreSQL (`labflow_postgres`) | Контейнер `running`, health-check `healthy`, БД `labflow_db` доступна |
| Backend (`labflow_backend`) | Контейнер `running`, `GET /health` → `{"status":"healthy"}` |
| Swagger | `GET http://localhost:8000/docs` → HTTP 200 |
| Frontend (`labflow_frontend`) | `GET http://localhost:3000` → HTTP 200, интерфейс загружается |
| Данные | Volume `postgres_data` сохраняет данные между перезапусками |
| Изоляция | Контур работает локально, без обращения к внешним БД и API |

## 3. Smoke-чек-лист

| № | Проверка | Команда / способ | Ожидаемый результат | Факт | Статус |
|---|---|---|---|---|---|
| 1 | Валидность compose-файла | `docker compose config` | Конфигурация без ошибок | Ошибок нет | Passed |
| 2 | Чистая сборка и запуск | `docker compose up --build -d` | Все сервисы запущены | Запуск успешен | Passed |
| 3 | Статус контейнеров | `docker compose ps` | Три контейнера в состоянии `running` | `postgres`, `backend`, `frontend` — `running` | Passed |
| 4 | Health-check PostgreSQL | `docker inspect --format='{{.State.Health.Status}}' labflow_postgres` | `healthy` | `healthy` | Passed |
| 5 | PostgreSQL принимает подключения | `docker exec labflow_postgres pg_isready -U labflow_user -d labflow_db` | `accepting connections` | `accepting connections` | Passed |
| 6 | БД доступна с хоста | `psql -h localhost -p 5432 -U labflow_user -d labflow_db -c '\dt'` | Подключение успешно, таблицы доступны | Подключение успешно | Passed |
| 7 | Схема БД создана | `\dt` в `psql` | Таблицы приложения присутствуют | Таблицы созданы | Passed |
| 8 | Backend health-check | `curl http://localhost:8000/health` | HTTP 200, `{"status":"healthy"}` | HTTP 200, тело корректно | Passed |
| 9 | Swagger/OpenAPI доступен | `curl -o NUL -w "%{http_code}" http://localhost:8000/docs` | HTTP 200 | HTTP 200 | Passed |
| 10 | OpenAPI-схема отдаётся | `GET http://localhost:8000/openapi.json` | HTTP 200, валидный JSON | HTTP 200, JSON валиден | Passed |
| 11 | Frontend доступен | `curl -o NUL -w "%{http_code}" http://localhost:3000` | HTTP 200 | HTTP 200 | Passed |
| 12 | Frontend отдаёт приложение | Открытие `http://localhost:3000` в браузере | Страница загружается, критичных ошибок в консоли нет | Страница загружается | Passed |
| 13 | Порядок запуска соблюдён | `docker compose logs backend` | Backend стартовал после готовности БД, ошибок подключения нет | Ошибок подключения нет | Passed |
| 14 | Перезапуск PostgreSQL | `docker compose restart postgres` + повторная проверка `/health` | Данные сохранены, backend восстанавливает соединение | Данные сохранены, health-check проходит | Passed |
| 15 | Полный перезапуск контура | `docker compose down` → `docker compose up -d` | Контур поднимается, данные на месте | Поднялся, данные на месте | Passed |
| 16 | Логи без критичных ошибок | `docker compose logs --tail=100` | Нет `ERROR`/`CRITICAL`, влияющих на работу | Критичных ошибок нет | Passed |
| 17 | Загрузка/скачивание файла | Проверка файлового сценария | Файл сохраняется и скачивается | MinIO отсутствует в текущем compose | Not run |
| 18 | Отправка Telegram-уведомления | Проверка события `NEW_SUBMISSION` | Уведомление доставлено или замокано | Требуется токен/мок | Not run |

**Итого:** 16 из 16 применимых проверок пройдено. 2 проверки отложены, так как зависят от сервисов, которых нет в текущем контуре (MinIO) или требуют внешних учётных данных (Telegram).

## 4. Выявленные замечания

| № | Замечание | Severity | Статус |
|---|---|---|---|
| 1 | MinIO не описан в `docker-compose.yml`, хотя файловые сценарии входят в MVP | Major (риск покрытия) | Открыто, вынесено в риски тест-плана |
| 2 | При занятом порту `5432` контур не стартует | Minor | Обход: `POSTGRES_PORT=5433` в `.env` |
| 3 | Пароли по умолчанию из `.env.example` непригодны для staging | Minor | Зафиксировано ограничение локального контура |

Критичных дефектов, блокирующих тестирование, не обнаружено.

## 5. Ограничения прогона

- Проверка выполнялась на локальном Docker Desktop; различия ОС и версий Docker на машинах команды могут влиять на первый запуск.
- Файловые и Telegram-сценарии не входят в текущий smoke-набор до появления MinIO и тестового бота; они проверяются отдельно после расширения контура.
- Smoke-набор проверяет доступность и связность, но не корректность бизнес-логики — это задача функциональных тест-кейсов.

## 6. Выводы

Окружение после чистой сборки поднимается одной командой, все заявленные сервисы доступны, PostgreSQL healthy, backend и frontend отвечают, данные сохраняются между перезапусками. Окружение готово к функциональному тестированию.

**Решение QA:** smoke-тесты считать пройденными; допустить окружение к прогону функциональных тест-кейсов. Риск по MinIO учитывать при планировании проверок загрузки отчётов.

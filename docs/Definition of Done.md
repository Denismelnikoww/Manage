## 1. Назначение и границы DoD

Документ фиксирует **Definition of Done (DoD)** для веб-сервиса **LabFlow** в рамках MVP: одна академическая группа ВПР42, роли «Студент» / «Преподаватель», 5 детерминированных статусов работы (`Не начата` → `В работе` → `Сдана` → `На доработке` → `Принята`).

**DoD не переписывает критерии приёмки (AC).** AC 1.1–12.2 зафиксированы в [[User Stories|User Stories]] и являются источником истины. DoD определяет **общие условия**, при которых User Story может считаться завершённой, и **условия закрытия вехи**.

**Источники формирования DoD:**

- [[User Stories|User Stories]] — AC 1.1–12.2, матрица трассировки FR-01…FR-10.
    
- [[Use Cases|Use Cases]] — UC-01…UC-08, матрица жизненного цикла статусов (раздел 3), исключения и альтернативные потоки.

## 2. DoD уровня User Story (US-01…US-12)

История считается «Done», только если выполнены **все** пункты без исключений.

| №   | Критерий DoD                                                                            | Как проверить                        | Источник          |     |
| --- | --------------------------------------------------------------------------------------- | ------------------------------------ | ----------------- | --- |
| D1  | Все AC истории пройдены на 100%, без статуса «частично»                                 | Тест-кейсы, статус Passed            | User Stories      |     |
| D2  | Нет открытых багов Severity Blocker/Critical/Major по истории                           | Баг-трекер, фильтр по US             | —                 |     |
| D3  | Функциональность работает на тестовом окружении (staging)                               | Ручной прогон                        | —                 |     |
| D4  | Роли разграничены: студент не имеет доступа к teacher-эндпоинтам (403)                  | AC 1.3 + матрица ролей               | US-01, UC-01      |     |
| D5  | Валидация выполняется на клиенте **и** на сервере (нельзя обойти прямым API-вызовом)    | Postman/curl в обход UI              | AC 6.2, UC-04     |     |
| D6  | Ошибки возвращают корректные HTTP-коды и понятные сообщения                             | Негативные сценарии                  | UC-01, UC-04      |     |

| D8  | События для Telegram генерируются (`NEW_SUBMISSION`, `STATUS_CHANGED_*`, `NEW_COMMENT`) | Логи бэкенда / мок Telegram          | UC-04, UC-06      |     |
| D9  | Регресс смежных модулей не сломан                                                       | Смоук-набор + регресс по трассировке | Матрица FR        |     |
| D10 | Контракты API (OpenAPI) соответствуют фактическому поведению                            | Сверка контрактов                    | —                 |     |

## 3. DoD уровня вехи «Проектирование завершено» (WBS 5.1.1)

|№|Критерий|Ответственный|
|---|---|---|
|S1|Все 12 US имеют AC в Given-When-Then и трассировку к UC и FR|Аналитик|
|S2|Матрица трассировки FR-01…FR-10 заполнена на 100%|Аналитик + QA|
|S3|Для каждого AC есть минимум 1 позитивный и 1 негативный тест-кейс|QA|
|S4|Все Must Have истории пройдены на staging|QA|
|S5|Should/Could (FR-09, FR-10) проверены, но не блокируют веху|QA|
|S6|Баг-репорты оформлены по шаблону (шаги, ожидаемо/фактически, severity)|QA|
|S7|Отчёт о приёмке подписан (чек-лист приёмки)|QA + PO|

## 4. DoD уровня MVP (релизный)

Релиз MVP считается готовым, когда одновременно выполнены:

|№|Критерий|Источник|
|---|---|---|
|M1|Все Must Have требования FR-01…FR-08 покрыты пройденными тест-кейсами|Матрица трассировки|
|M2|Все переходы матрицы жизненного цикла статусов проверены (разрешённые и запрещённые)|Use Cases, раздел 3|
|M3|Негативные сценарии из Use Cases воспроизведены и обработаны корректно: 401, 403, 500 + откат, блокировка «На доработку» без комментария, сбой MinIO, 429 Telegram|UC-01, UC-04, UC-06, UC-08|
|M4|Граничные значения проверены: 20 МБ, 5 символов, 3 дня / 0 / −1, 15 минут pre-signed URL, 10 секунд SLA, 3 попытки retry|User Stories + Use Cases|
|M5|Out of Scope MVP не реализован и не влияет на работу сервиса (командная сдача, CI runner, интеграция с деканатом/Moodle, чат в реальном времени)|Use Cases, раздел 1|
|M6|Отчёт о приёмке MVP оформлен и подписан QA + PO|—|

## 5. Чек-лист подтверждения DoD (подпись QA)

Перед закрытием задачи 3.1.2 QA подтверждает:

- 
    DoD уровня User Story (D1–D10) определён и применим ко всем US-01…US-12.
- 
    Матрица применимости DoD по историям (раздел 2.1) заполнена.
- 
    DoD уровня вехи (S1–S7) согласован с аналитиком и PO.
- 
    DoD уровня MVP (M1–M6) зафиксирован.
- 
    DoD не противоречит AC из User Stories и сценариям из Use Cases.
- 
    Документ утверждён и передан в работу QA для формирования тест-плана.

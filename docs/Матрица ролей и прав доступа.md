## 1. Введение и модель безопасности

Настоящий документ регламентирует политику разграничения прав доступа в веб-сервисе **LabFlow** на базе ролевого доступа (**RBAC — Role-Based Access Control**) и атрибутивного контроля владения ресурсами (**ABAC — Attribute-Based Access Control** / Object-Level Permissions).

Сервис строго разделяет пользовательские привилегии для обеспечения информационной безопасности, изоляции академических данных студентов и защиты прав преподавателя на выставление рецензий и оценок.

### Базовые аксиомы безопасности:
1. **Принцип наименьших привилегий (Principle of Least Privilege):** Каждый субъект системы наделен минимально достаточным объемом прав для выполнения своих обязанностей.
2. **Нулевое доверие к клиенту (Zero Client Trust):** Все проверки ролей и прав владения объектами выполняются строго на стороне бэкенда (`FastAPI`). Валидация в UI (`React`) служит исключительно для улучшения пользовательского опыта (UX) и скрытия недоступных элементов управления.
3. **Строгая изоляция студенческих данных:** Студент никогда не имеет права просматривать сданные файлы, комментарии или персональные статусы других студентов группы.
4. **Защита от несанкционированного изменения статусов:** Преподаватель не может сдавать работы за студента, а студент не может самостоятельно утверждать свои работы или возвращать их на доработку.

## 2. Идентификация и классификация субъектов (Ролей)

В системе определены 4 типа субъектов взаимодействия:

| Субъект / Роль | Обозначение в API | Механизм аутентификации | Описание и область ответственности |
|---|:---:|---|---|
| **Гость (Анонимный)** | `anonymous` | Без токена | Неавторизованный посетитель веб-приложения. Имеет доступ только к страницам входа, регистрации и служебным ресурсам (OpenAPI/Swagger docs). |
| **Студент** | `student` | Bearer JWT (Access Token) | Обучающийся академической группы ВПР42. Просматривает назначенные работы и дедлайны, берет работу в выполнение, загружает файл отчета (PDF/DOCX/ZIP), скачивает свой сданный отчет, читает рецензии преподавателя, подключает Telegram. |
| **Преподаватель** | `teacher` | Bearer JWT (Access Token) | Преподаватель или ассистент курса. Создает, обновляет и удаляет задания (CRUD), просматривает сводную ведомость группы, скачивает отчеты любого студента, комментирует и утверждает вердикты («Принята» / «На доработке»). |
| **Система / Бот** | `system_bot` | Секретный токен в заголовке `X-Service-Token` | Фоновый микросервис Telegram-бота на базе `aiogram3`. Выполняет межсервисную привязку `chat_id` пользователя по одноразовому токену без вмешательства пользовательской сессии. |

## 3. Архитектура аутентификации и токены

### 3.1. Структура пользовательского JWT-токена (Bearer)
При успешной аутентификации через `POST /api/v1/auth/login` бэкенд формирует подписанный токен `HMAC-SHA256`:

```json
{
  "sub": "123e4567-e89b-12d3-a456-426614174000",
  "email": "student.ivanov@edu.local",
  "role": "student",
  "group_name": "ВПР42",
  "full_name": "Иванов Иван Иванович",
  "iat": 1730718000,
  "exp": 1730804400
}
```

- **Срок действия токена:** 24 часа (86 400 секунд).
- **Передача токена:** Заголовок HTTP-запроса `Authorization: Bearer <access_token>`.

### 3.2. Межсервисный токен (Service-to-Service)
Для внутренних системных вызовов Telegram-бота используется фиксированный секретный токен:
- **Передача токена:** Заголовок HTTP-запроса `X-Service-Token: <SECRET_BOT_API_KEY>`.
- **Область применения:** Строго эндпоинт `POST /api/v1/telegram/internal/bind`. Все остальные маршруты отклоняют данный токен с ошибкой `401/403`.

## 4. Сводная матрица доступа к эндпоинтам API

Обозначения прав:
- 🟢 **ALLOW** — Доступ разрешен без ограничений.
- 🟡 **OWN** — Доступ разрешен **только к собственным ресурсам** (Object-Level Ownership Check). Доступ к чужим записям блокируется (`403 Forbidden`).
- 🔴 **DENY** — Доступ категорически запрещен (`403 Forbidden` для авторизованных, `401 Unauthorized` для анонимных).

| HTTP Метод | URI Эндпоинта | Operation ID | Аноним (`anon`) | Студент (`student`) | Преподаватель (`teacher`) | Бот (`system`) | Описание и контекстные правила доступа |

| **POST** | `/auth/login` | `loginUser` | 🟢 ALLOW | 🔴 DENY | 🔴 DENY | 🔴 DENY | Аутентификация по email/паролю, выдача JWT токена. |
| **GET** | `/auth/me` | `getCurrentUser` | 🔴 DENY | 🟢 ALLOW | 🟢 ALLOW | 🔴 DENY | Получение профиля текущего пользователя по JWT. |

## 5. Матрица полномочий при переходах жизненного цикла (FSM)

Каждая лабораторная работа каждого студента находится в одном из 5 детерминированных статусов. Права на перевод работы между состояниями строго распределены между акторами:

| Исходный статус | Целевой статус | Разрешенный актор | Эндпоинт и действие | Дополнительные условия и проверки | Поведение при нарушении прав |
|---|---|:---:|---|---|---|
| `not_started` | `in_progress` | **Студент** | `PATCH /submissions/{id}/status` `{ "status": "in_progress" }` | Студент является владельцем сдачи (`student_id == current_user.id`). | `403 Forbidden` (если чужая сдача или инициировано преподавателем) |
| `not_started` | `submitted` | **Студент** | `POST /submissions/{id}/upload` *(multipart/form-data)* | Загрузка файла (PDF/DOCX/ZIP ≤ 20 МБ). Статус переводится сервером автоматически. | `400 Bad Request` (неверный формат/размер) или `403 Forbidden` |
| `in_progress` | `submitted` | **Студент** | `POST /submissions/{id}/upload` *(multipart/form-data)* | Загрузка файла (PDF/DOCX/ZIP ≤ 20 МБ). Статус переводится сервером автоматически. | `400 Bad Request` (неверный формат/размер) или `403 Forbidden` |
| `submitted` | `accepted` | **Преподаватель** | `PATCH /submissions/{id}/status` `{ "status": "accepted" }` | Роль пользователя — `teacher`. Опционально сохраняется комментарий. | `403 Forbidden` (если пытается перевести студент) |
| `submitted` | `needs_work`| **Преподаватель** | `PATCH /submissions/{id}/status` `{ "status": "needs_work", "comment_text": "..." }` | Роль — `teacher`. Наличие содержательного комментария с замечаниями (длина ≥ 5 символов) **строго обязательно**. | `400 Bad Request` (нет комментария) или `403 Forbidden` (не преподаватель) |
| `needs_work` | `submitted` | **Студент** | `POST /submissions/{id}/upload` *(multipart/form-data)* | Студент исправляет замечания и загружает обновленный файл отчета. | `403 Forbidden` (если чужая сдача или пытается преподаватель) |
| `accepted` | *Любой другой*| ❌ **НИКТО** | — | Статус `Принята` является терминальным финальным состоянием защиты работы. Модификация заблокирована. | `409 Conflict` («Работа уже защищена и не может быть изменена») |
| `submitted` | `submitted` | ❌ **Студент** | `POST /submissions/{id}/upload` | Повторная загрузка заблокирована, пока преподаватель не проверит текущий отчет. | `409 Conflict` («Работа находится на проверке у преподавателя») |

## 6. Политики доступа к файлам и хранилищу MinIO

Хранилище MinIO изолировано от прямого публичного доступа из интернета:
1. **Загрузка (Upload):**
   - Студент передает бинарный файл через бэкенд LabFlow (`multipart/form-data`).
   - Бэкенд валидирует права студента, MIME-тип (PDF, DOCX, ZIP) и размер (до 20 МБ).
   - Бэкенд под сервисной учетной записью MinIO сохраняет файл в приватный бакет `labflow-submissions` по структурированному пути: `submissions/{lab_id}/{student_id}/{timestamp}_{filename}`.
2. **Скачивание (Download via Pre-Signed URL):**
   - Прямой доступ к файлам по статическим URL запрещен.
   - Клиент запрашивает временную ссылку через эндпоинт `GET /api/v1/submissions/{id}/download-url`.
   - Бэкенд выполняет проверку прав:
     - Если запрос от студента: `submission.student_id == current_user.id`. Иначе — `403 Forbidden`.
     - Если запрос от преподавателя: доступ разрешен ко всем студентам группы.
   - При успешной валидации бэкенд запрашивает у MinIO временный криптографически подписанный URL (**Pre-signed URL**) с временем жизни строго **15 минут** (900 секунд).
   - По истечении 15 минут выданная ссылка становится недействительной, исключая утечку академических работ.

## 7. Коды ошибок авторизации и правила безопасности

Бэкенд возвращает стандартизированные ответы об ошибках в формате JSON:

```json
{
  "code": "FORBIDDEN",
  "message": "У вас нет прав для выполнения данного действия или доступа к ресурсу",
  "details": []
}
```

| HTTP Код ошибки | Стандартная причина возникновения | Примеры в бизнес-логике LabFlow |
|:---:|---|---|
| **401 Unauthorized** | Отсутствует, поврежден или просрочен Bearer JWT токен в заголовке `Authorization`. | - Попытка вызова `/labs` без авторизации.<br>- Время жизни токена (24 ч) истекло.<br>- Неверный email или пароль при логине. |
| **403 Forbidden** | Токен валиден, но у субъекта недостаточно прав (несоответствие роли или попытка доступа к чужому объекту). | - Студент пытается вызвать `POST /labs` (создание работы).<br>- Студент А пытается скачать отчет студента Б (`GET /submissions/{id_B}/download-url`).<br>- Преподаватель пытается вызвать `POST /submissions/{id}/upload`.<br>- Студент пытается поставить статус `accepted`. |
| **404 Not Found** | Запрашиваемый ресурс не существует в БД. | - Запрос работы по несуществующему `lab_id`.<br>- Работа помечена как удаленная (`is_deleted = true`). |
| **409 Conflict** | Действие противоречит текущему состоянию конечного автомата. | - Повторная отправка отчета, когда работа уже имеет статус `submitted` или `accepted`.<br>- Регистрация с уже существующим email. |

> [!CAUTION] Защита от утечки информации (IDOR Prevention)
> Если студент пытается запросить чужую сдачу `GET /api/v1/submissions/{id_another_student}`, бэкенд возвращает **403 Forbidden** (либо **404 Not Found** для предотвращения сканирования существующих идентификаторов в системе).

## 8. Архитектурный шаблон реализации на бэкенде (FastAPI)

Для обеспечения надежного контроля доступа в кодовой базе бэкенда (`FastAPI`) используются внедрение зависимостей (`Depends`) и цепочка валидаторов:

```python
from fastapi import APIRouter, Depends, HTTPException, status
from app.models import User, UserRole, StudentSubmission
from app.auth import get_current_user

router = APIRouter(prefix="/submissions", tags=["Submissions"])

# Фабрика зависимостей для проверки роли
def require_role(allowed_roles: list[UserRole]):
    def role_checker(current_user: User = Depends(get_current_user)):
        if current_user.role not in allowed_roles:
            raise HTTPException(
                status_code=status.HTTP_403_FORBIDDEN,
                detail="Недостаточно прав для выполнения данной операции"
            )
        return current_user
    return role_checker

# Проверка владения объектом сдачи (Object-Level Ownership Check)
async def get_submission_with_owner_check(
    submission_id: str,
    current_user: User = Depends(get_current_user)
) -> StudentSubmission:
    submission = await StudentSubmission.get_or_none(id=submission_id)
    if not submission:
        raise HTTPException(status_code=404, detail="Сдача не найдена")
    
    # Преподавателю доступны все сдачи
    if current_user.role == UserRole.TEACHER:
        return submission
    
    # Студенту доступна только своя сдача
    if submission.student_id != current_user.id:
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail="Доступ к материалам другого студента запрещен"
        )
    return submission

@router.get("/{submission_id}/download-url")
async def download_report(
    submission: StudentSubmission = Depends(get_submission_with_owner_check)
):
    # Генерация pre-signed URL в MinIO на 15 минут
    url = generate_minio_presigned_url(submission.file_path, expires=900)
    return {"download_url": url, "expires_in_seconds": 900}
```

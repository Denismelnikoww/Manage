## 1. Цель работ

Разработать исчерпывающий набор критериев приёмки и детальных тест-кейсов для функционального модуля **«4.4. Отчёты и комментарии»**, обеспечивающий проверку:
1. Корректности загрузки отчётов студентами (PDF, DOCX, ZIP) через проксирующий эндпоинт бэкенда в бакет MinIO (`MINIO_BUCKET_REPORTS`).
2. Строгой серверной валидации типов по magic bytes, лимитов размера (`0 < size ≤ 20 971 520` байт), защиты от zip-bomb, null-байтов и path traversal в именах файлов.
3. Разграничения прав доступа (RBAC/ABAC): студент может загружать и скачивать только свои работы; преподаватель может просматривать и скачивать отчёты любых студентов курируемой группы; чужие работы изолированы (`403 Forbidden`).
4. Жизненного цикла статусов сдачи: переход в `submitted` при загрузке, блокировка повторной отправки в статусах `submitted` и `accepted` (`409 Conflict`), разблокировка загрузки новой версии в статусе `needs_work` (US-09).
5. Безопасности выдачи и скачивания через **Pre-signed GET URL** (TTL 900 с, AWS SigV4, `Content-Disposition: attachment; filename*=UTF-8''...`).
6. Транзакционной целостности: расчёт и проверка контрольной суммы SHA-256, компенсирующее удаление объекта из MinIO при сбое PostgreSQL (`DoD D7`), сохранение неизменности статусов при сбое S3.
7. Рецензирования преподавателем: добавление комментариев, обязательность текста замечания (≥ 5 символов) при вердикте «На доработке», экранирование HTML от XSS.
8. UI-сценариев: drag-and-drop файлов, индикация загрузки, блокировка элементов интерфейса.

## 6. Негативные сценарии безопасности и фаззинг

| Вектор атаки / Сценарий | Механизм защиты | Ожидаемый результат проверки |
|---|---|---|
| **Zip-bomb (архив с распаковкой 100 ГБ)** | В MVP архив `.zip` **не распаковывается** на стороне сервера, а сохраняется как единый blob в MinIO. Проверяется только заголовок архива | Сервер не подвержен атаке исчерпания диска/RAM при получении zip-bomb |
| **MIME-spoofing (подмена заголовка Content-Type)** | Сервер не доверяет заголовку клиента, а анализирует сигнатуру первых 512 байт | Файл с типом `application/pdf`, содержащий сигнатуру PE/ELF (`MZ`), отклоняется |
| **Path Traversal через имя файла** | Принудительная санитизация: удаление последовательностей `../`, null-байтов `\x00` | Имя файла не может выйти за пределы каталога объекта в бакете |
| **Подделка подписи Pre-signed URL** | Подпись вычисляется с использованием секретного ключа MinIO по стандарту AWS SigV4 | Изменение хотя бы одного байта в параметрах query приводит к ошибке `403 SignatureDoesNotMatch` от MinIO |

## 8. Выводы и рекомендации для команды разработки

1. Подготовленный набор из **65 тест-кейсов** гарантирует 100% покрытие требований `FR-04`, `FR-05`, `NFR-04`, критериев приёмки `AC 6.1–6.4`, `AC 7.1–7.3`, `AC 8.1–8.3`, `AC 9.1–9.2` и правил Definition of Done.

### Роли пользователей

| **Роль**          | Описание                                                                                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Студент**       | Просматривает список лабораторных работ и дедлайны, загружает отчёты, отслеживает статус своей работы, читает комментарии преподавателя, получает уведомления в Telegram |
| **Преподаватель** | Создаёт и редактирует работы и дедлайны, просматривает загруженные отчёты, комментирует, меняет статусы работ, получает уведомления о новых сдачах                       |
### Функциональные требования

| Требование                                                                                                 | Приоритет |
| ---------------------------------------------------------------------------------------------------------- | --------- |
| Аутентификация и авторизация пользователей с разграничением ролей «студент» / «преподаватель»              | Must      |
| CRUD лабораторных работ: название, описание, дедлайн, привязка к учебной группе                            | Must      |
| Отслеживание статусов работы: не начата / в работе / сдана / на доработке / принята                        | Must      |
| Загрузка отчёта студентом (файл) и его хранение в MinIO; скачивание отчёта преподавателем                  | Must      |
| Комментирование работы преподавателем                                                                      | Must      |
| Telegram-уведомления: студенту - о смене статуса и новом комментарии; преподавателю - о новой сдаче отчёта | Must      |
| Просмотр студентом списка своих работ с дедлайнами и текущими статусами                                    | Must      |
| Просмотр преподавателем списка работ группы и статусов сдачи по каждому студенту                           | Must      |
| Фильтрация/сортировка работ по статусу и дедлайну                                                          | Should    |
| История изменений статуса работы (кто и когда изменил)                                                     | Could     |
### Нефункциональные требования

| Требование                                                                                                         | Приоритет |
| ------------------------------------------------------------------------------------------------------------------ | --------- |
| Стек: Backend - Python 3.14, FastAPI, aiogram3, MinIO; Frontend - TypeScript, React, SCSS, HTML; СУБД - PostgreSQL | Must      |
| Развёртывание одной командой `docker compose up`; CI через Git/GitHub + Docker Compose                             | Must      |
| Ключевые страницы открываются менее чем за 2 с при локальном развёртывании                                         | Should    |
| Доступ к загруженным отчётам - только авторизованным пользователям с соответствующими правами                      | Must      |
| Тестовые события доставляются в Telegram при доступном API                                                         | Should    |
| Адаптивность интерфейса и кроссбраузерность (Chrome, Firefox, Edge)                                                | Should    |
| Документация ведётся в Obsidian; требования трассированы к задачам и тест-кейсам                                   | Must      |
### Ограничения и допущения

- **Сроки:** старт - 26.10.2026, защита 20.12.2026.
- **Состав:** 6 человек, по одной роли на участника; доступное время - 6–8 ч/нед на человека.
- **Внешние зависимости:** Telegram Bot API, MinIO, PostgreSQL.
